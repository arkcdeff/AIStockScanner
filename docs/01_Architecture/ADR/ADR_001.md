# ADR-001: Technology Stack Selection

## Status
Accepted

## Date
2024-01-15

## Context
We need to select a technology stack for the AI Stock Scanner project that supports:
- Async operations for high-performance API
- PostgreSQL database with async driver
- Technical indicator calculations
- Clean architecture with separation of concerns

## Decision

### Backend Framework: FastAPI
- **Rationale**: Native async support, automatic OpenAPI docs, high performance, type hints via Pydantic
- **Alternatives considered**: Django REST Framework, Flask
- **Trade-offs**: Less mature than Django, but better async performance

### ORM: SQLAlchemy 2.x
- **Rationale**: Modern async ORM, mature ecosystem, excellent PostgreSQL support
- **Alternatives considered**: Tortoise ORM, Peewee
- **Trade-offs**: More complex than Tortoise, but better production maturity

### Async Driver: asyncpg
- **Rationale**: Fastest async PostgreSQL driver, native protocol
- **Alternatives considered**: psycopg3 async
- **Trade-offs**: Lower-level API, but better performance

### Indicators: pandas-ta
- **Rationale**: 100+ technical indicators, pandas-native API
- **Alternatives considered**: TA-Lib, tulipy
- **Trade-offs**: pandas-ta is pure Python, TA-Lib requires C bindings

### Database: PostgreSQL 18
- **Rationale**: ACID compliance, excellent performance, rich data types
- **Alternatives considered**: MySQL, SQLite
- **Trade-offs**: Heavier than SQLite, but better for production scale

## Consequences
- Async-first architecture requires careful session management
- SQLAlchemy 2.x query API differs from 1.x
- pandas-ta calculations may be CPU-intensive for large datasets
- PostgreSQL required for production deployment
